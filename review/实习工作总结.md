## 三、A3-power武器开发
2025/07/20 - 2025/08/10
a3-power 是一个用于采集并上报硬件功耗数据的轻量级监控组件。
它的主要功能是：
通过底层工具（如 ipmitool、devmem 等）读取服务器或设备的实时功耗信息；
将采集到的数据转换为 Prometheus 可识别的指标格式（即 /metrics 接口输出）；
为功耗监控、能耗分析、算力优化等场景提供基础数据支持。
### 1.数据采集服务启动

1. 将以下四个文件放在同一目录下：

   * `a3power_prometheus`
   * `prometheus.yaml`
   * `ipmitool`
   * `devmem`
2. 在对应目录下执行命令启动a3power软件：
   ```bash
   ./a3power_prometheus
   ```
3. 启动成功后，可通过访问：
   `http://<服务器IP>:<端口号>/metrics`
   验证服务是否正常运行。端口号可在 `prometheus.yaml` 中查看。


### 2.Prometheus 部署

1. 按部署教程在服务器上配置 Prometheus 环境。
2. 若采集目标为其他服务器（例如另一台机器的 8000 端口），只需修改 `prometheus.yml` 中的采集目标地址：

   ```yaml
   targets: ["<目标IP>:8000"]
   ```
3. 其余配置及端口保持不变，路径根据实际部署位置调整。
4. 浏览器访问 Prometheus 对应端口，若能看到监控界面，说明启动成功。

### 3.常见问题与解决方案

1. **Shell 语法错误**

   * 报错信息：`syntax error near unexpected token '>'`
   * 原因：脚本使用 Bash 特有语法 `>(...)`，不能用 `sh` 执行。
   * 解决：使用以下命令启动：

     ```bash
     bash run_prometheus.sh
     ```

2. **可执行文件架构不匹配**

   * 报错信息：`cannot execute binary file: Exec format error`
   * 原因：在 x86 架构系统上运行 ARM 版本程序。
   * 检查方式：

     ```bash
     uname -m       # 查看系统架构
     file prometheus  # 查看二进制文件架构
     ```
   * 解决：从 Prometheus 官方发布页下载与系统架构匹配的版本（例如 x86-64 对应 Linux-amd64）。

3. **参数不兼容**

   * 报错信息：`unknown long flag '--storage.tsdb.retention'`
   * 原因：新版 Prometheus 参数名变更。
   * 解决：将脚本中参数修改为：

     ```bash
     --storage.tsdb.retention.time="30d"
     ```

## 四、数据集上传权限校验
### 1. 获取业务处理器

```java
SystemUploadCheckInterface systemUploadInterface = getSupportType(systemUploadRequest.getBusinessType());
```

这行代码的意思是：
根据 `systemUploadRequest` 中传入的业务类型（`businessType`），动态选择一个 **对应的上传处理器**。

* 系统中存在多个实现了 `SystemUploadCheckInterface` 接口的类，它们分别负责处理不同类型的上传任务；
* `getSupportType()` 会从一个缓存映射（下面那行 `Map`）中取出对应的实现类。
这是一个典型的 **策略模式 (Strategy Pattern)** 的用法。

---

### 2. 权限认证与校验

```java
TokenKit tokenKit = authBaseService.authToken(httpRequest);
authBaseService.authPrivilege(
    PrivilegeRuleEnum.OPERATOR, 
    tokenKit.getPrivileges(),
    systemUploadInterface.supportedViewResourceEnums(), 
    true
);
```

这部分完成 **安全认证和权限验证**：

* `authToken(httpRequest)`：
  从 HTTP 请求中提取并验证用户身份令牌（Token），返回包含权限信息的 `TokenKit` 对象；

* `authPrivilege(...)`：
  校验当前用户是否有执行该上传操作的权限。
  参数含义：
  * `PrivilegeRuleEnum.OPERATOR`：要求的权限类型（操作权限）；
  * `tokenKit.getPrivileges()`：用户拥有的权限；
  * `systemUploadInterface.supportedViewResourceEnums()`：该上传类型支持的资源类型范围；
  * `true`：是否严格校验（无权限则报错）。

### 3. 上传服务实现类缓存

```java
private final Map<String, SystemUploadCheckInterface> systemUploadOperationServiceCacheMap
        = new ConcurrentHashMap<>();
```

这是一个线程安全的缓存，用来存储：

> “业务类型” → “上传服务实现类” 的映射关系。

例如：

```java
{
  "model_upload" -> ModelUploadServiceImpl,
  "config_upload" -> ConfigUploadServiceImpl
}
```

使用 `ConcurrentHashMap` 保证多线程环境下并发读取/写入的安全性。
配合前面的 `getSupportType()`，可以快速根据业务类型找到对应处理逻辑，而无需频繁创建新对象。

---

通过 Spring 的依赖注入机制注入 `WeaponExecutorService`。负责执行后续的任务（如上传后的检测、分析或调度执行），

## 五、Redis-benchmark武器开发
### 1.Redis 概述
Redis（Remote Dictionary Server）是一种开源的高性能 **内存型键值数据库（NoSQL）**，支持多种数据结构如 `String`、`Hash`、`List`、`Set`、`ZSet` 等。
其核心特性包括：
1. **高性能**：数据完全存储在内存中，每秒可执行数十万次读写操作。
2. **多数据结构支持**：除键值外，支持复杂的数据存储模型。
3. **持久化机制**：可将数据异步保存到磁盘，防止数据丢失。
4. **主从复制与备份**：支持主从架构，实现高可用性和数据安全。
5. **丰富功能**：包括发布/订阅、键过期、事务、Lua脚本等。
Redis 常用于缓存、会话管理、消息队列、排行榜及实时统计等场景。
### 2.Redis 安装
1. 下载安装包后，使用 `tar` 解压并放置到指定目录（如 `/usr/local/redis`）。
2. 使用 `make` 编译，`make install` 安装可执行文件到系统路径。
3. 可通过 `redis-cli -v` 验证安装是否成功。
4. 启动方式：
   ```bash
   ./redis-server
   ```
   启动后可通过 `redis-cli` 进行连接和测试。
   安装过程中可使用 `PREFIX` 参数指定安装路径，方便管理和卸载。
### 3.性能测试工具 redis-benchmark
`redis-benchmark` 是 Redis 自带的官方性能测试工具，用于模拟不同负载下的客户端请求场景，评估 Redis 实例在特定环境下的性能表现。
它可用于：
* 评估部署环境性能；
* 比较不同配置或硬件下的表现；
* 验证 Redis 优化效果。

### 4.常用测试参数

| 参数        | 含义               | 示例           |
| ----------- | ------------------ | -------------- |
| `-h`        | Redis 服务器地址   | `-h 127.0.0.1` |
| `-p`        | 端口号（默认6379） | `-p 6379`      |
| `-a`        | 密码认证           | `-a password`  |
| `-n`        | 请求总数           | `-n 100000`    |
| `-c`        | 并发客户端数量     | `-c 50`        |
| `-d`        | 数据大小（字节）   | `-d 128`       |
| `-t`        | 指定测试命令       | `-t get,set`   |
| `-r`        | 随机 key 空间大小  | `-r 10000`     |
| `-P`        | pipeline 请求数    | `-P 16`        |
| `-q`        | 仅输出查询速率     | `-q`           |
| `--csv`     | 以 CSV 格式输出    | `--csv`        |
| `--cluster` | 启用集群模式       | `--cluster`    |
---
redis-benchmark 是 Redis 性能测试和优化的重要工具。
通过设置不同参数组合，可模拟多种业务负载场景，从而评估 Redis 的响应能力与并发性能，为后续性能调优提供数据支撑。

### 5.武器开发
#### WeaponExecute

该脚本的主要功能是 **自动构建 redis-benchmark 命令并执行测试**，将测试结果保存到文件中。
1. **参数初始化**
   从平台传入的参数中获取 Redis 连接信息和压测参数：

   * `host`：Redis 地址
   * `port`：端口号
   * `password`：连接密码
   * `total`、`clients`、`data_size`：请求数量、并发数、数据大小
   * `test_cmds`：测试命令（如 get/set）
   * `threads`、`cluster`：线程数、是否集群模式

2. **参数校验 `_check_benchmark_param()`**
   * 校验 IP 格式是否合法
   * 校验端口号是否在合法范围内（1-65535）
3. **构造命令 `_generate_redis_benchmark_cmd()`**
   根据参数拼接 redis-benchmark 命令，例如：
   ```bash
   ./redis-benchmark -h 127.0.0.1 -p 6379 -n 100000 -c 50 -t get,set
   ```
   同时可自动添加密码、key空间、集群模式等参数。
4. **执行命令 `_run_task_cmd()`**
   * 使用 `subprocess.Popen` 执行命令；
   * 实时将输出写入日志和结果文件 `result.txt`；
5. **输出结果**
   * 所有输出写入 `TASK_RESULT_PATH/{task_id}/result.txt`；
   * 为后续分析阶段提供原始数据。
#### WeaponAnalysis

该脚本的主要功能是 **解析 redis-benchmark 输出结果**，提取性能指标（如 QPS、延迟）并生成标准化汇总文件。
1. **读取结果文件**
   * 打开 `result.txt`；
   * 若文件不存在或读取失败，则抛出异常。
2. **解析结果段落**
   * 使用正则表达式提取每个测试命令块（如 `SET`、`GET`）；
   * 每个块包含 throughput（QPS）和 latency（延迟）信息。
3. **提取性能指标**
   * `get_qps()`：提取 “throughput summary” 后的 QPS 值；
   * `parse_latency()`：提取平均延迟、最小值、P50、P95、P99、最大值。
4. **组织结构化数据**
   * 将每种操作类型（GET/SET）的性能数据封装为 `SummaryData`；
   * 组装成 `SummaryResult`，以便平台生成图表或报表。
5. **输出汇总文件**
   * 调用 `summary_result.to_file()` 将结果保存到标准路径；
   * 输出指标表包括：
   | 操作类型 | QPS | AVG | MIN | P50 | P95 | P99 | MAX |

## 六、MCP-server自动创建性能压测任务
### 1.MCP介绍
MCP是一种依托大语言模型推理能力实现的智能调用机制，本质属于提示词工程。它通过自然语言描述来明确MCP Server的功能定位和各个MCP Tool的作用范围，使模型能够自动选择最合适的工具来完成任务。

MCP的核心由Server端和Client端组成。Server负责提供功能接口（即MCP Tool），Client负责与大模型交互并根据模型推理结果调用对应的Tool。

在Server端，开发者通过定义不同的tool函数来提供具体能力，例如返回系统时间、查询用户信息或获取环境数据。Server通过SSE方式运行，保持与Client的长连接以持续响应请求。

Client端（如Cline插件）在配置好Server地址后，可直接调用这些tool。当用户提出问题时，大模型会根据系统提示词推理出应调用的具体工具及参数，随后Client通过SSE向Server发起请求并返回结果。

总体来看，MCP的机制流程包括三步：

1. 大模型根据提示词推理并选择合适的Tool；
2. Client通过SSE与Server交互获取Tool执行结果；
3. 大模型基于结果生成综合回答。

MCP的创新在于将自然语言推理与工具调用融合，使模型具备了“理解需求—选取工具—执行任务—输出结果”的完整闭环能力。
该项目是一个基于MCP协议构建的多功能服务器系统，主要用于批量生成和管理性能压测作业。整个系统采用模块化设计，代码结构清晰，职责划分明确，通过MCP Server机制实现与大模型和外部工具的智能交互。

### 2.实现架构
项目的核心文件为 `yuntan_mcp_server.py`，该文件通过引入 `FastMCP` 框架快速搭建MCP服务端，定义并注册一系列性能压测相关的工具接口（tool），这些接口能够接收客户端请求，调用后端服务逻辑完成任务生成、压测调度、数据集管理、环境初始化以及结果汇总等操作。MCP Server以SSE流式通信方式运行，保证与MCP Client之间的持续连接与结果推送。

系统主要模块包括以下几个部分：

1. **common模块**：定义系统常量与日志配置。`constant`目录中保存任务描述、任务类型等常量文件；`log_config`中通过`logger_util.py`实现统一日志管理与输出控制。
2. **config模块**：用于存放服务器运行配置，包括`server_config.py`与对应的`server_config.yaml`文件，负责加载MCP服务运行所需的端口、地址、接口路径等配置信息。
3. **infrastructure模块**：实现与外部系统的通信逻辑。`client/yuntan`目录下的`auth.py`提供认证与权限校验；`large_model_task_client.py`负责与云端大模型任务管理系统交互，用于环境ID、任务状态和模型任务的统一管理。
4. **service模块**：是系统的业务核心，包含多个子模块。

   * `dataset`用于数据集管理和加载；
   * `environment`负责环境信息查询与部署；
   * `evaluation`负责模型评估任务范围定义；
   * `pressure`用于性能压测任务生成与执行逻辑封装；
   * `task_group`负责任务分组、调度与执行流程管理；
   * `weapon`模块封装与压测工具（如Redis benchmark、Weapon SDK）相关的业务逻辑。
5. **utils模块**：提供系统级辅助函数，如`url_utils.py`中定义统一的URL拼接与请求格式化工具，确保与后端系统交互的一致性。

该系统的实现流程是：
用户通过MCP Client发起压测请求，MCP Server接收后根据任务类型调用相应的service模块；service模块通过infrastructure层与大模型任务系统、性能执行框架等进行交互，生成具体的压测作业。通过MCP的自然语言接口，用户可以直接以命令式语句创建、调度和查询压测任务，实现了性能测试的自动化与智能化。

总体而言，该MCP服务器通过模块化结构、SSE长连接通信机制及多层服务封装，构建了一个可扩展、可管理、可自动化运行的性能压测平台，为大规模系统性能验证与模型推理能力评估提供了高效的支撑。

### 3.灵雀平台的部署
当然，以下是一版简洁、适合放入工作汇报或PPT的流程总结：
1. **创建工作空间与智能体**

   * 向管理员申请独立空间
   * 进入 *项目开发 → 应用*，新建智能体并完成基本配置
2. **添加 MCP 工具插件**
   * 在智能体设置中添加“发现和调用 MCP 工具”
   * 在“信息与设置”中填写 MCP Server 参数（替换为本地 server 地址）
3. **测试连接与防火墙开通**
   * 若连接失败，申请开通防火墙策略
   * 配置 Source（灵雀 IP）与 Destination（本地 MCP Server IP）
   * 审批通过后验证连接
4. **发布与验证**
   * 测试连接成功后，发布运行智能体
   * 在应用界面确认发布成功，空间成员即可使用
